# TODO Scheduler

Планировщик задач с веб-интерфейсом, REST API на Go и хранением данных в SQLite. Помогает вести список дел и автоматически рассчитывать следующую дату для повторяющихся задач.

Учебный дипломный проект курса «Go-разработчик с нуля» Яндекс Практикума, принятый на итоговом ревью. Backend реализован в рамках задания курса; фронтенд и исходный набор проверочных тестов предоставлены в шаблоне проекта.

**Стек:** Go, net/http, encoding/json, SQL, SQLite (modernc.org/sqlite), JWT (golang-jwt/jwt/v5), Docker. Проверки используют testing и Testify.

Приложение позволяет:

* добавлять задачи;
* получать список ближайших задач;
* искать задачи по заголовку, комментарию или дате;
* получать одну задачу по идентификатору;
* редактировать и удалять задачи;
* отмечать задачи выполненными;
* автоматически переносить периодические задачи на следующую дату;
* ограничивать доступ к API с помощью пароля и JWT-токена.

Фронтенд расположен в директории `web` и раздаётся самим Go-сервером.

## Дополнительные возможности

В проекте реализованы:

* настройка порта через `TODO_PORT`;
* настройка пути к SQLite через `TODO_DBFILE`;
* еженедельные правила повторения `w`;
* ежемесячные правила повторения `m`;
* поиск задач по заголовку и комментарию;
* поиск задач по дате;
* аутентификация через `TODO_PASSWORD` и JWT;
* Dockerfile для сборки и запуска приложения.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/signin` | Вход по паролю и получение JWT |
| GET | `/api/nextdate` | Расчёт следующей даты по правилу повторения |
| POST | `/api/task` | Создание задачи |
| GET | `/api/tasks` | Список задач и поиск |
| GET | `/api/task?id=...` | Получение задачи |
| PUT | `/api/task` | Редактирование задачи |
| DELETE | `/api/task?id=...` | Удаление задачи |
| POST | `/api/task/done?id=...` | Выполнение задачи |

Выполнение одноразовой задачи удаляет её. Для повторяющейся задачи сервер сохраняет следующую дату выполнения. Поддерживаются интервалы в днях, ежегодные, еженедельные и ежемесячные правила.

При включённой аутентификации операции с задачами требуют JWT. Вход и расчёт следующей даты остаются открытыми.

## Требования

Для локального запуска необходим Go версии 1.25 или новее.

Для запуска в контейнере необходим Docker.

## Локальный запуск

Команды ниже рассчитаны на Bash, в том числе Ubuntu/WSL. Клонировать репозиторий и скачать зависимости:

```bash
git clone https://github.com/exis7ence/final_project.git
cd final_project
go mod download
```

Запустить без аутентификации:

```bash
go run .
```

По умолчанию сервер доступен по адресу:

```text
http://localhost:7540/
```

Запуск с настройками через переменные окружения:

```bash
TODO_PORT=7540 \
TODO_DBFILE=./scheduler.db \
TODO_PASSWORD=12345 \
go run .
```

При включённом пароле страница входа доступна по адресу:

```text
http://localhost:7540/login.html
```

## Переменные окружения

| Переменная      | Назначение          | Значение по умолчанию |
| --------------- | ------------------- | --------------------- |
| `TODO_PORT`     | Порт HTTP-сервера   | `7540`                |
| `TODO_DBFILE`   | Путь к файлу SQLite | `scheduler.db`        |
| `TODO_PASSWORD` | Пароль для доступа  | пустая строка         |

Если `TODO_PASSWORD` не задан, проверка аутентификации отключена.

## Запуск тестов

Проверочные тесты взаимодействуют с запущенным сервером и изменяют данные в SQLite, включая удаление задач. Запускайте их в отдельной копии проекта с тестовой базой, без личных задач.

Перед тестированием необходимо запустить сервер.

Без аутентификации:

```bash
go run .
```

В другом терминале:

```bash
go test -count=1 ./tests
```

Рекомендуемые настройки в `tests/settings.go`:

```go
var Port = 7540
var DBFile = "../scheduler.db"
var FullNextDate = true
var Search = true
var Token = ``
```

Для тестирования с аутентификацией сервер запускается так:

```bash
TODO_PASSWORD=12345 go run .
```

Токен можно получить запросом:

```bash
curl -s -X POST \
  -H "Content-Type: application/json" \
  -d '{"password":"12345"}' \
  http://localhost:7540/api/signin
```

Полученное значение поля `token` нужно временно указать в `tests/settings.go`:

```go
var Token = `полученный-JWT-токен`
```

Токен не следует сохранять в Git.

## Сборка Docker-образа

```bash
docker build -t final-project .
```

## Запуск через Docker

Создать директорию для базы данных:

```bash
mkdir -p data
```

Запустить контейнер:

```bash
docker run --rm \
  --name final-project \
  -p 7540:7540 \
  --mount type=bind,src="$(pwd)/data",dst=/data \
  -e TODO_PASSWORD=12345 \
  final-project
```

Открыть в браузере:

```text
http://localhost:7540/login.html
```

Файл базы данных сохраняется на хосте:

```text
data/scheduler.db
```

Для запуска без пароля параметр `-e TODO_PASSWORD=12345` можно убрать.

Пароль `12345` в командах приведён только для локального примера; при использовании аутентификации задайте собственный пароль.

## Что отработано в проекте

- Разделение HTTP-обработчиков, операций с данными и запуска сервера.
- Работа с SQL и SQLite, валидация JSON и параметров запросов.
- Расчёт календарных правил повторения задач.
- Обработка ошибок API: коды 400, 401, 404, 405 и 500 вместо успешного ответа при ошибке.
- Разделение внутренних ошибок базы и публичных сообщений: детали записываются в лог, клиент получает нейтральное сообщение.
- Конфигурация через переменные окружения и сохранение базы вне Docker-контейнера.

Один из выводов после ревью: успешный запуск приложения недостаточен для проверки API. Нужно отдельно проверять некорректный JSON, неподдерживаемые методы, отсутствующие задачи и ошибки базы.
